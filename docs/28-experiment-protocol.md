## 适用范围

**只管"要跑一段真实市场才能判好坏"的改动**：策略参数、机制开关、报价/退出行为、
风控阈值。这类改动的正确性不由测试决定，由预注册判据 + live 读数决定。

纯工程改动（重构、类型化、CLI、遥测 schema）不走这套，走 [AGENTS.md](../AGENTS.md)
的 Pre-Merge Verification。两者的分界：**改动是否可能影响成交结果**。
唯一例外是收紧风险的改动，见[风险方向规则](#风险方向规则收紧可立即生效放宽须先登记)。

## 四件套（缺一不开跑）

| # | 产物 | 位置 | 可变性 |
|---|------|------|--------|
| 1 | 立项设计 | `docs/NN-*-design.md`（机制、开关、红线） | 开跑前可改 |
| 2 | 预注册判据 | 写在立项文档里，**开跑前 commit 入库** | 开跑后冻结 |
| 3 | 启动记录 | commit（授权文本 + 首臂 UTC 时间戳 + 配置 sha256 + git sha） | 追加 |
| 4 | 判定报告 | `docs/evidence/*-YYYY-MM-DD.md` | 不可变 |

判据在开跑后**只能作废整轮，不能修改**。改了判据的实验等于没有判据。

判定词汇固定四个，不要自创：`accepted` / `rejected` / `ab_completed_not_accepted`
（跑完了但没达标）/ `rejected_split_branch`（组合被拒但拆出子候选另立项）。

## 预注册判据模板

```markdown
### 预注册判据（YYYY-MM-DD 入库，开跑后冻结）

- 目标函数：<一句话。例：少亏 —— 净 PnL 的下行被压住，不要求变正>
- 臂长与样本量：<例：4h/臂，3 对 6 臂，最小成交数 N>
- 裁决人：<release owner>

**运维门槛（任一不过 → rejected）**
- [ ] 双边 uptime ≥ <绝对值>%   ← 用绝对值，不要用"相对基线降 ≤Npp"
- [ ] 零安全违规（无未解释仓位失配、无残余单、无 fail-open）
- [ ] manifest valid，cycle 序列完整

**经济门槛**
- [ ] <指标 + 方向 + 门槛值>

**红线（越线即 rejected，与门槛分开写）**
- <例：倾斜不得把报价推出 SIP-5A 10bps 合格带——那是变相停挂>

**明确不作为晋级条件的指标（必填，不许留空）**
| 指标 | 为什么不作条件 | 谁在什么时候补 |
|------|----------------|----------------|
| <例：净 PnL> | <市况不可比，A/B 只回答相对问题> | <登记到下方未判项表> |
```

最后一栏是这份模板的重点。允许"PnL 不作晋级条件"让实验推得动，但**代价必须显式记账**——
否则连续两次晋级之后，没有人说得清基线是否赚钱（这正是 2026-07 实际发生的事）。

## 硬规则（都是付过代价换来的）

1. **离线记账不得作为晋级依据。** 8→12bps 加宽在离线反事实里为正，live 6 臂判负
   （净 -1.86 vs -5.04/笔，成交率 9–11/h vs 2.7–5.7/h），离线高估 >100%，直接导致
   阶段 4 的漂移前倾控制器整个取消。离线分析只能用来**排除**候选和排优先级，
   不能用来批准上线。
2. **两臂只允许差一行配置。** 例：`maker-stage3-hype-{baseline,candidate}.toml` 只差
   `size_skew.enabled`。差两行的实验解释不了因果。
3. **组合候选必须可拆单纯配置重跑。** 一个 release 里两个独立开关（stage3v1 =
   非线性 skew + 外部价防御门），组合被拒时拆单不重锁代码、不重走 canary。
4. **冻结基线用 sha256 入档**，启动前 `shasum -a 256` 复核，跑动期间一个字节都不改。
5. **判据的门槛值改动要记谁裁决的、什么时候。** 例：uptime 判据从"相对降 ≤3pp"改为
   "≥80% 绝对值"是 release owner 2026-07-22 的裁决，写在判定报告里。
6. **owner 推翻判定，报告必须标 `override`。** 判据结果与 owner 的最终决定不一致时（判据
   未达标但 owner 采纳，或判据达标但 owner 否决），判定报告单列一行 `override`，写明裁决人、
   时间、被推翻的判据与读数、理由。仍然给出判据本身的结论，`override` 是标签，不是第五个
   判定词，不替代 `accepted` / `rejected` 等四个词。没有这一行的"采纳"，按判据结果读。

## 基线绝对读数的停止条件（笔数优先）

适用对象：[27 号手册](27-maker-baseline-pnl-collection-runbook.md) 的单臂绝对 PnL 采集，
**不适用于 A/B 臂**（A/B 的臂长和最小成交数仍按各自预注册判据）。时长不能代替样本量：淡市下
72h 可以只有个位数成交（2026-10-08 窗口在 6h53m 到 12h53m 之间只新增 2 笔）。

- **停止条件：累计 200 笔成交，或 14 天，以先到者为准。** 成交笔数取当前 run 账本的
  `fills_total`（即读数模板里的 fills），不取外部或历史成交。两个数字写进授权文本，随启动记录
  入库，开跑后冻结，不得中途改。
- 27 号手册里"2–3 天"的时长是历史默认值；新授权文本按本节写停止条件。（本 PR 不改 27 号手册，
  由后续手册更新同步。）
- **`underpowered` 标注：** 14 天先到而成交不足 200 笔时，读数照常报告，但判定报告和台账都必须
  标 `underpowered`，该读数不得用来断言基线"赚钱"或"不赚钱"，也不关闭下方未判项表里的
  "冻结基线净 PnL"。延长窗口、放宽条件或接受该读数，都是 owner 裁决，按硬规则 6 记录。
- 其他终止原因（owner 中断、fail-safe 退出、残单、失配、uptime 门槛未过）不受影响：整轮按
  截断或作废处理，不因为"差几笔"而续算。笔数达到 200 时仍要通过运维门槛，才算一次完整读数。

**A/B 规划用估算（不是停止条件）。** 用来规划后续 A/B 要多长、能分辨多大的每笔净 PnL 差：
按 BTC 历史被动成交的分布粗估，分辨 ±2bps/笔约需 280 笔，±1.5bps 约 500 笔，考虑成交聚簇
和重尾后约 550–1000 笔，即 **280–1000 笔**（来源：
[maker-perfill-stop-tail-2026-08-21](evidence/maker-perfill-stop-tail-2026-08-21.md) 的 n=231 窗口，
σ 取两点混合的下界约 17bps，只是量级）。每个 A/B 立项按自己的数据重算 σ 和有效样本，写进预注册的
"臂长与样本量"，不直接套用这组数字。

## 风险方向规则：收紧可立即生效，放宽须先登记

上面"是否可能影响成交结果"的分界有一个例外，按改动方向分：

| 方向 | 例子 | 要求 |
|------|------|------|
| **收紧风险** | 调低 size / `max_position` / 止损阈值；更早停机；更严的 fail-closed | 可以立即生效，不需要预注册。提交说明里必须写明：改了什么、为什么是收紧、对正在跑的窗口和读数可比性的影响 |
| **放宽或放大** | 调高限额；放大 size；放宽停机或 fail-closed 条件；启用任何新机制 | 必须先按四件套预注册（立项设计 + 判据入库），再改 |

- 无法明确归为"收紧"的改动（同时改了报价行为、一收一放、方向取决于市况），按放宽处理。
- 收紧可能改变成交（例：`max_divergence_bps` 15→8 会多跳周期），所以立即生效不等于不影响读数：
  正在跑的冻结基线或 A/B 窗口照旧按硬规则 4 处理，即截断或作废，不续算；先例见
  [34](34-maker-btc-migration-2026-08-21.md) run4 截断记录。
- 收紧同样要过 [AGENTS.md](../AGENTS.md) 的测试和评审要求；新机制仍须默认关闭并有字节等价测试。
  这条规则只免去预注册，不免去验证。

## 未判项登记

每次"不作为晋级条件"的指标进这张表，直到它被单独回答。**这张表不许有长期停滞行。**

| 未判项 | 因哪轮被搁置 | 为什么不作条件 | 补它的方式 | 状态 |
|--------|--------------|----------------|------------|------|
| 冻结基线净 PnL | 阶段 3 skew（07-25 accepted）、阶段 3-guard（07-27 accepted） | 臂间市况不可比，A/B 只回答相对问题 | [27 号手册](27-maker-baseline-pnl-collection-runbook.md) 单臂 2–3 天绝对读数采集 | 进行中（等 owner 填授权文本） |
| SIP-5A $/MH 收入 | 全程 | owner 决定目标函数为"少亏"，当前规模收入≈0 | 规模发生量级变化时重开 | 已关闭（owner 裁决） |

## 不实施的方案 → 观测项，不进 backlog

评估后决定不做的方案，不要留成"待办"。降级为观测项时**三样一起给**，否则它会腐烂：

1. **立项触发条件**（预注册，可判定的量）
2. **证据来源**（哪份手册的哪个每日记录字段）
3. **复核时点**

范例（2026-07-16 divergence 事故四方案的 07-28 处置，见
[docs/evidence/maker-divergence-degradation-review-2026-07-28.md](evidence/maker-divergence-degradation-review-2026-07-28.md)）：
方案 C 因熔断器已从代码移除而**直接关闭**（无豁免对象 → 不写代码）；B/D 降为观测项，
触发条件"单次 standby >10min，或窗口内累计 >1% 运行时间，或证明发生在阈值上方悬停"，
证据来源指定为 27 号手册的 `divergence_standby` / `transport_standby` 每日记录。

**推论：方案清单要定期复核。** 代码会演进到让方案本身失效，照着两周前的方案施工会
写出没有对象的代码。

## 校验器误报的处置

manifest / 判定脚本 fail-closed 误判时，**做窄容忍 + 记一条根因 issue，绝不放宽整体校验**。
范例：A/B 期间两次误判（freeze-retried 重复 cycle `be445fb`、freeze-lost 缺 cycle
`7d6b6ee`）在工具侧精确容忍，同时把运行时"每 cycle 必发终态事件"记为根治候选。
