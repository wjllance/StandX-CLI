# markout 尾部分解与外部信号判别力（2026-08-01，两个 baseline-pnl run，纯离线只读）

**这份文档只报读数与推论边界，不给晋级/否决结论。** 它是两件事的依据：候选 4
（[`[external_skew]`](../28-maker-external-skew-design.md)）的**价值上限**，以及尾部避让类
机制的**立项证据**。

## 数据来源

两个独立 run，同一配置（`examples/maker-guard-hype-candidate.toml`，sha256
`6314a374…`，原样），不同代码 sha：

| | run | 代码 | 窗口 | 被动成交 |
|---|---|---|---|---|
| 上轮 | `baseline-pnl-20260728T081712Z` | `819f0f0` | 35.9h（fail-safe 截断） | 527 |
| 本轮 | `baseline-pnl-20260731T030133Z`（run4） | 含两帧 ack 修复 | 36h 时点切片（未收尾） | 513 / 522（按口径） |

被动成交笔数因过滤口径略有差异（513 = 净额对账用的口径，522 = 买卖分组口径）。
本轮 36h 时点净读数：净亏 **-1.66 DUSD**（≈权益 0.9%）、毛利 +1.42、手续费 -0.27，
离 `stop_loss=5.0` 尚远，无安全事件。

**口径**：本文全部 markout 为 **script 口径**（从成交时的 mark 起算，**不含**
capture），与 [28 号验收判据](../28-maker-external-skew-design.md)预注册的口径一致。
遥测的 `performance.markout_*` 是 runner 口径（从成交价起算、含 capture），两者差一个
capture，**数字不可互换**。

## 发现 1：markout 曲线在 30s 饱和，没有长尾

| 视界 | 本轮 | 上轮 |
|---|---|---|
| 30s | -7.8 | -7.9 |
| 60s | -8.4 | -8.2 |
| 300s | -8.1 | -8.7 |
| 900s | -8.0 | -8.2 |

30s 之后到 15 分钟基本走平；负占比从 30s 的 **83%** 降到 900s 的 **58%**（多数成交在
30s 之后仍在修复）。

**推论**：不存在"越拖越亏"的长尾。此前"伤害可能延伸到 1~5 分钟、因而 30s 视界低估
损失"的假设**被否**。逆选伤害在 30 秒内完成，正是外部领先价信号的有效窗口。

## 发现 2：净额对账 —— 30s markout 已解释全部净亏

```
capture +2.8 bps  −  markout@30s 7.8 bps  −  手续费 ≈1 bps  ≈  −6 bps/笔
−6 bps × 513 笔 × ~5.5 名义  ≈  −1.66  =  会话净亏
```

**推论**：不存在"找不到原因的另一半亏损"。此前的"一半无法解释"是**口径混用造成的
重复计数**（把含 capture 的 runner markout 当作毛伤害，又另计一遍毛利），不是隐藏的
损失来源。

## 发现 3：亏损尾部主导，不是均匀渗透

| 分组 | mo300 均值 | 占 markout 亏损质量 |
|---|---|---|
| 最差 10%（n≈103 两轮合计） | **-53 ~ -58 bps** | **60~72%** |
| 其余 90% | -2.5 ~ -4.0 bps | 28~40% |

有毒成交的已知特征：**单龄小**（中位 **9~26 秒**，刚挂上就被打穿）、成交前 drift 略大。

**推论**：问题不是"每笔都差一点"，而是"少数几笔被打穿"。对策方向相应地是**识别并避开
那 10%**（新单保护、打穿即撤一类），而不是把所有报价都挪一点。

## 发现 4：外部 excess 对尾部无判别力

有毒 10% 与其余 90% 在成交时刻的外部偏离度**几乎同分布**：

| | 有毒 10% | 其余 90% |
|---|---|---|
| 本轮 \|div\| 均值 / p90 | 4.04 / 6.96 | 3.83 / 7.24 |
| 上轮 \|div\| 均值 / p90 | 3.54 / 5.95 | 3.60 / 6.69 |
| 带符号（买 / 卖，raw） | -2.7~-2.8 / +3.7~+4.2 | -3.3~-3.4 / +3.3~+3.5 |
| guard 激活占比 | **0%** | <1% |

`external_guard` 的 `enter_bps=10` 阈值在这 103 笔有毒成交里**一次都没够着**。

**推论**：尾部是**场内**成因（扫单 / 本所逆选），外部领先价对它没有预警能力。这与
[28 号立项依据 (d)](../28-maker-external-skew-design.md)"残余毒性、其余是场内流量"的
预判方向一致，本文把它从定性警告量化成了边界。

## 发现 5：立项依据 (b) 三样本复现

成交时刻的 excess 系统性逆向，原始值（不做任何取反）：

| 样本 | 买单 | 卖单 |
|---|---|---|
| 28 号文档 (b)（上轮 19.4h 切片，n=289） | -3.2 | +3.65 |
| 上轮全窗（n=527） | -3.25 | +3.31 |
| 本轮 36h（n=522） | -3.35 | +3.53 |

三个独立样本全部落在文档值 **±0.35bps** 内。买单在外部价偏低时被吃、卖单在外部价偏高
时被吃，方向与"外部领先、StandX 跟随"完全一致。

**推论**：(b) 从单次读数升级为三样本复现，候选 4 的靶子是真实且稳定的——**但它主要
落在其余 90% 里**（见发现 4）。

## 对候选 4 的含义：价值上限的阶梯

| 口径 | 量级 | 占当前净亏 |
|---|---|---|
| 现实（λ=0.5，[28 号 (c)](../28-maker-external-skew-design.md) 反事实） | +0.27 / 35h | ~16% |
| 理想（其余 90% 的 markout 全部消除） | +0.6 ~ 1.1 / 35h | 36~66% |
| 尾部那 60~72% | **碰不到** | — |

- **`[external_skew]` 是"改善价格"的机制，不是"避开成交"的机制**：它让每笔成交的价格
  好一点点，不阻止坏成交发生。尾部要的恰恰是后者。两者**不互斥、不重叠**。
- **即使达标，策略仍不赚钱**：回收的是净亏的 ~16%（现实口径），大头结构上在本机制
  之外。这不构成否决理由（16% 是真钱），但裁决时不能按"这一个就能救活"来批。
- **两个百分比的口径不同，别读成打架**：尾部占 **markout 亏损质量**的 60~72%；而"全砍
  其余 90%"能拿回**净亏**的 36~66%——差别在于那些成交的 capture 收入仍然保留。

## 已知限制

- **亚秒级漏检**：本文用的是 guard 自己的 divergence 信号（cycle 级 ~2.4s 粒度）。若外部
  领先发生在亚秒级且在成交前已回落，这个口径会漏掉。但那种幅度也不在
  `[external_skew]`（λ×excess，cap 8bps）的作用范围内，不影响结论方向。
- ~~**单龄 / drift 只是线索，成因未验证**：一个待查假设是"我们自己撞上去"~~
  **已于 2026-08-02 查证并证伪**，见下节。
- **盘口量不可回溯**：档位厚薄从未落日志（microprice 类候选一直被此阻塞），故"薄档位"
  一类前置特征在现有数据上无法检验。
- **"亏损放缓"未裁决**：本轮前 20h 亏 1.5、后 17h 仅亏 0.16。库存重估是最大单项且随
  价格方向变动，因此该放缓**很可能是横盘 regime 而非策略改善**——判别法是把两段的逐笔
  markout 分开算（markout 是逐笔属性，不随 regime 走），**尚未做**。
- 本轮 run 未收尾，以上为 36h 时点切片；收尾后应复核数字是否漂移。

## 追加（2026-08-02）：refresh-born 归因 —— "我们自己撞上去"被证伪

**结论先说：假设方向反了。** 有毒成交里 refresh 重挂产生的单占比**更低**，不是更高。

### 字段核查与定义自洽性

两个 run 的字段与预期一致（`place` 无 `order_id`、`cancel` 带 `reason`、`fill` 带
`mark_at_fill` / `trade_id`）。`cancel.reason` 实际只出现 4 个值：
`mark_moved`（run1 5821 次 / run4 4669 次）、`side_suppressed`、`would_cross`、
`outside_band`，**无 `stale`**。成交全部 `role=passive_maker`、单侧 `level=0`，满足
按 `(side, level, price)` 回放归因的前提。

**定义自洽性已验证**：**100% 的 `mark_moved` 撤单都伴随同 cycle 同侧重挂**，故
"refresh-born =（同 cycle 同侧存在 `reason=mark_moved` 的撤单）"这个定义无系统偏差。
副产品：一张单是否 refresh-born **完全由前一张同侧单的离场原因决定**。

### 前置判别力检查（通过）

全体挂单 refresh-born 占比 **81.8%**（12823 笔中 10490；两 run 分别 81.9% / 81.7%），
未越过 >90% 的红线，查法有效。但对照组只是那 18.2%，**读数时的注意力应放在"什么样的
单不是 refresh-born"上**。

未能归因的成交 68/1063（6.4%），其 mo300 均值 -6.4bps，不偏向有毒 —— 排除归因失败
造成的选择偏差。

### 表 1 主表（Fisher 精确检验）

| | run1 (n=496) | run4 (n=499) | 池化 (n=995) |
|---|---|---|---|
| 有毒 10% 中 refresh-born | 28/49 = 57.1% | 28/49 = 57.1% | **56/99 = 56.6%** |
| 其余 90% 中 refresh-born | 313/447 = 70.0% | 317/449 = 70.6% | **630/895 = 70.4%** |
| 差 / OR / p | -12.9pp / 0.57 / 0.074 | -13.5pp / 0.56 / 0.072 | **-13.8pp / 0.55 / 0.006** |

绝对阈值复核（mo300 < -25bps，池化 n=217）：58.1% vs 72.1%，-14.0pp，p=0.0001。
**两个分组口径同向**，结论不敏感于十分位切法。

（有毒组 n=99 而非 ≈103：差异来自池化十分位口径 + 1 笔 horizon 截尾，不影响结论。）

### 表 2 分层（池化，trailing 60s 已实现波动三分位）

| 层 | 有毒 rb% | 其余 rb% | 差 | p |
|---|---|---|---|---|
| slow | 66.7% | 76.6% | -9.9pp | 0.25 |
| mid | 56.4% | 73.0% | -16.6pp | 0.039 |
| fast | 48.5% | 61.5% | -13.1pp | 0.19 |

**三层全为负**，不是行情速度造出的假关联。每层有毒 ~33 笔，只读方向不读量级。

### 表 3 方向一致性（池化，decile 口径）

| 组 | sign 一致率（15s / 30s） | 双负率 | pearson / spearman（drift_place30 vs mo30） |
|---|---|---|---|
| 有毒 | 54% / 58% | 48% / 55% | **+0.27 / +0.27** |
| 其余 | 56% / 53% | 47% / 45% | +0.08 / +0.06 |

一致率差异很弱，**"被碾过"的直接证据不强**。稍强的一条是：有毒组内 `drift_place` 对
mo30 的解释力（r≈0.27）明显高于其余组（0.08）—— 那批单确实是挂进了一段有方向性的移动。

### 表 1b 那 43% 非 refresh-born 的有毒单是什么

非 refresh-born 意味着该侧报价不是被撤掉而是**消失了**，主要场景是我们自己的上一笔
同侧成交。距上一笔同侧成交的时间：

| 组 | 中位 | <30s 占比 |
|---|---|---|
| 有毒 | 138s | 32% |
| 其余 | 226s | 22% |

方向两个 run 一致，但量级中等 —— **只能解释有毒单的约 1/4 ~ 1/3**。

### 判定与对候选 6 的影响

结果落在预设判定表**没有的一行**：占比差异显著但方向相反。

1. **"refresh 撤单重挂送单上门"证伪。** refresh-born 的单反而更不容易有毒。
2. **`refresh_bps` 这个旋钮应因证据不足撤出候选 6，而不是反向采纳。** 有人会想"那就抬高
   `refresh_bps` 让单待久点" —— 这一步推不出来，因为**"非 refresh-born"不是一个东西**：
   按表 1b，它的主因是"报价消失后重新进场"（补挂），而抬 `refresh_bps` 造出来的是"没被
   换掉的老单"，两个群体不同。**且有一条直接反向的证据**：有毒成交单龄中位仅 9~26s，
   即年轻的单更毒，而抬 `refresh_bps` 会让单平均更老 —— 方向相反。两条线互相抵消，
   说明这组数据对该旋钮**没有判别力**。
3. **机制形态转向"成交后补挂纪律"**（同侧成交后延迟 / 加宽补挂），而非"refresh 重挂
   纪律"。但表 1b 只覆盖约 1/4~1/3 的有毒单，**剩下的仍指向"单挂在原地被带信息的对手方
   扫走"**（新单保护 / 打穿即撤那一支）。数据不支持二选一干净结案，两条线都保留。

### 价值上限（修订）

每 36h 尾部 markout 亏损约 1.51；若"成交后冷却"能砍掉其中 1/3 的有毒单，约
**+0.50 / 36h ≈ 净亏的 30%**（避开成交损失的 capture 极小，可忽略）。

| 杠杆 | 上限（占净亏） |
|---|---|
| 候选 4（`external_skew`） | ~16% |
| 候选 6 的"成交后冷却"这一支 | **~30%** |
| 剩下 2/3 的尾部 | 尚无机制 |

即候选 6 约值候选 4 的**两倍**，不是四倍（60~72% 的尾部**不等于**可达范围）。
**两个都做满仍不到盈亏平衡**：整条尾部全砍掉，剩余 90% 每笔仍差约 1.4bps。

### 一个待验证的新假设：成交扎堆（大单分批执行）

三条独立读数可以是同一件事：

1. 有毒单集中在"刚被成交后重新挂上"的那批（表 1b）；
2. 有毒组的 `drift_place` 对 mo30 有解释力（表 3，r≈0.27）—— 挂进了延续中的方向性移动；
3. **mo30 的 deff 1.8→3.1 且 4h 未封顶**（07-31 block bootstrap）—— 毒性在时间上成簇。

即：**一个大单在分批执行 —— 扫掉我方一次，我方补挂，它继续扫。** 若成立，机制形态
不是"保护每一张新单"，而是**成交后对该侧设冷却**，且触发条件应挂在那笔成交自身的不利
特征上（90% 的成交是好的，无条件冷却会白扔 uptime 与 capture）。

**能直接判死的检验**：同侧成交序列中毒性的自相关 —— 一笔有毒成交之后，下一笔同侧成交
是否也更可能有毒。成立则"流延续"确立；不成立则砍掉该支，回到"原地被挑走"。

### 下一步（三个查询，均不占 live 时间片）

1. **四格单龄分布**（有毒/其余 × refresh-born/非 rb 的单龄中位与分位）—— 拆开"年龄"与
   "出生方式"哪个是真变量，决定 `refresh_bps` 旋钮是撤掉还是有救。
2. **有毒非 rb 单按前驱离场原因归因**（被自己成交 / `side_suppressed` / `would_cross` /
   `outside_band` / 无前驱）—— 比"距上次成交的时间"锐利，字段现成。同时把 gap 口径从
   "前一笔成交 → 本笔成交"改为**"前一笔成交 → 本单挂出"**（补挂在同 cycle 或下一 cycle，
   精确可得，无需代理）。
3. **同侧成交毒性的自相关** —— 判定成交扎堆假设。

### 本节的已知限制

- rvol 用 cycle mark（~2.45s 粒度）估算，分层边界因此是近似的。
- 表 1b 的 gap 是"上一笔同侧成交 → 本笔成交"，不是"成交 → 补挂"，**口径偏保守**
  （真实的补挂间隔更短，故该信号可能被低估）。
- 分层后每层有毒仅 ~33 笔，表 2 只读方向。
- 归因脚本 `scripts/maker_refresh_born_attribution.py`（回放逻辑与
  `maker_markout_ab.py` 的 `attribution_rows` 同口径，扩展记录挂单的 cycle / level）
  **尚未入仓**——本文档只记读数，脚本需另行提交。

## 作废记录

- **2026-08-01**：一度得出"有毒成交无外部预警 → 候选 4 碰不到靶子 → 应关闭"，**该结论
  作废**：当时对带符号 divergence 多乘了一个 side 符号，把系统性逆向读成了系统性顺向。
  发现 5 是修正后的原始值，(b) 复现。**发现 4（尾部无判别力）不受影响**——它建立在
  `|div|` 同分布与 guard 零激活上，与符号无关。
- **2026-08-02**：假设"有毒成交源于 refresh 撤单重挂（我们自己撞上去）"**被数据证伪**
  （方向相反，见追加节）。由该假设派生的"抬高 `refresh_bps`"这一配置级对策**同时作废**
  ——不是反向采纳，而是证据不足、撤出候选 6。
